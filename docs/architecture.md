# 项目架构（Architecture）

> 城投公司（地方政府融资平台，LGFV）信用研究的数据驱动框架。
> 目标：把分散在公开披露 PDF 中的非结构化信息，转化为**多主体 × 多年份**的可分析结构化数据，
> 支撑横向对比、趋势观察、区域聚合与风险预警。

---

## 一、分层架构

```
┌─────────────────────────────────────────────────────────────────┐
│  1. 数据采集层（原始文件，本地保存，不进仓库）                       │
│     raw_files/        样本 PDF（上海/成都/湖州/券商，手动下载）       │
│     shandong_reports/ 山东全量城投采集体系（爬虫 + 按城市归类 PDF）   │
└───────────────────────────────┬─────────────────────────────────┘
                                 │  pdfplumber / 爬虫解析
                                 ▼
┌─────────────────────────────────────────────────────────────────┐
│  2. 解析层（scripts/parse_report.py）                              │
│     从 PDF 提取字段 → 结构化 JSON（4 维度：基本信息/财务/评级/风险） │
└───────────────────────────────┬─────────────────────────────────┘
                                 │
                                 ▼
┌─────────────────────────────────────────────────────────────────┐
│  3. 数据层（data/）                                                │
│     data/mock/   合成模拟数据（chengtou_mock.json，进仓库，可复现） │
│     data/real/   真实数据区（本地，不进仓库；与 mock 同 schema）    │
└───────────────────────────────┬─────────────────────────────────┘
                                 │  分析脚本 / 看板
                                 ▼
┌─────────────────────────────────────────────────────────────────┐
│  4. 分析层（指标与模型）                                           │
│     KPI · 评级分布 · 杠杆率对比 · ROE/资产趋势 · 风险预警标签       │
└───────────────────────────────┬─────────────────────────────────┘
                                 │
                                 ▼
┌─────────────────────────────────────────────────────────────────┐
│  5. 展示层（index.html，自包含，无 CDN）                           │
│     内嵌模拟数据的交互看板 → GitHub Pages 公开演示                  │
└─────────────────────────────────────────────────────────────────┘
```

**设计原则**：每一层解耦，下层只向上层提供结构化数据；
真实数据缺失时，先用 `data/mock/` 把整套框架（尤其是展示层）跑通，再按相同 schema 灌入真实数据。

---

## 二、数据 Schema（四维度）

解析层产出的每条记录（单家主体 × 单年份）包含四组字段：

| 维度 | 关键字段 | 说明 |
|------|----------|------|
| 基本信息 | `short_name` `full_name` `province` `city` `industry` `rating` | 主体身份、属地、主体评级 |
| 财务指标 | `total_assets` `total_liabilities` `asset_liability_ratio` `operating_revenue` `net_profit` `roe` `ebitda_interest` `op_cf` `current_ratio` `quick_ratio` | 规模 / 杠杆 / 盈利 / 偿债 / 流动性 |
| 评级信息 | `issuer_rating` `bond_rating` `rating_agency` `rating_outlook` | 评级与展望 |
| 风险预警 | `risk_flags[]` | 由财务阈值自动触发的标签（见 methodology.md） |

完整示例见 `data/mock/chengtou_mock.json`。

## 三、目录结构（仓库内）

```
LGFVs/
├── README.md                  # 项目总览（首行为 GitHub Pages 链接）
├── index.html                 # 模拟数据展示看板（GitHub Pages 入口）
├── docs/
│   ├── architecture.md        # 本文件：架构与 schema
│   └── methodology.md         # 采集方法、字段定义、风险逻辑、数据保护
├── scripts/
│   └── parse_report.py        # 真实 PDF 解析参考实现（需本地 PDF，输出被 gitignore）
├── data/
│   └── mock/                  # 模拟数据（合成，可复现，进仓库）
│       ├── chengtou_mock.json #   8 家主体 × 5 年结构化数据
│       └── generate_mock_data.py  # 生成脚本（python generate_mock_data.py）
└── .gitignore                 # 保护原始/获取/隐私数据
```

> 本地另有 `raw_files/`、`shandong_reports/`、`reports/`，均被 `.gitignore` 排除，**绝不进入仓库**。

---

## 四、可复现性

- `data/mock/generate_mock_data.py` 使用固定随机种子（`SEED = 20260802`），
  多次运行结果一致；它一次性产出 `chengtou_mock.json` 与 `index.html`，保证"数据"与"展示"同源。
- `index.html` 内嵌数据，双击即可在浏览器打开，亦可直接作为 GitHub Pages 站点，无需任何服务器或外部依赖。

---

## 五、数据保护边界

| 类型 | 位置 | 是否进仓库 |
|------|------|-----------|
| 原始 PDF（手动下载样本） | `raw_files/` | ❌ 本地 |
| 真实采集数据（山东体系） | `shandong_reports/` | ❌ 本地 |
| 真实数据解析报告 | `reports/` | ❌ 本地（gitignore） |
| 合成模拟数据 | `data/mock/` | ✅ 进仓库 |
| 展示看板 | `index.html` | ✅ 进仓库（仅含模拟数据） |

未经显式确认，任何原始 / 获取 / 隐私数据均不上传。详见 `docs/methodology.md` 与 `README.md` 的"数据保护声明"。
