# 操作方法与方法论（Methodology）

> 本文说明数据的**采集 → 解析 → 结构化 → 分析 → 展示**全链路操作，以及数据保护原则。
> 适用于想复现、扩展或接入真实数据的协作者。

---

## 一、数据采集（原始文件）

数据来源为城投公司**公开披露**文件，主要包括：

| 文件类型 | 内容 | 典型来源 |
|----------|------|----------|
| 募集说明书 | 发行条款、发行人财务与评级 | 交易所 / 巨潮 / 公司公告 |
| 评级报告 | 主体/债项评级、展望、风险分析 | 评级机构官网 |
| 债权代理事务报告 | 年度偿债、财务摘要 | 承销商/受托管理人公告 |

两种获取方式：
1. **手动下载样本**：将代表性 PDF 存入 `raw_files/`（如上海/成都/湖州样本）。
2. **批量采集体系**：`shandong_reports/` 是一套已建成的山东省城投采集体系（爬虫脚本 + 按城市归类的原始 PDF + 采集进度），其内部脚本间使用相对路径互相引用，整体保留、结构不变。

> 两类原始文件均**只在本地保存**，不进入 Git 仓库（见 `.gitignore`）。

---

## 二、解析（PDF → 结构化字段）

参考实现：`scripts/parse_report.py`

- 从本地 PDF 提取 3 家样本（上海/成都/湖州）的结构化字段，生成横向对比 HTML 报告。
- 输出到 `reports/sample_report.html`（真实数据，**已被 gitignore 排除**）。
- 该脚本是**真实数据解析的模板**：接入新主体时，按相同 schema 增补提取函数即可。

也可替换为通用 PDF 解析（如 `pdfplumber` 做版面识别 + 正则/规则抽取关键指标），
关键是**输出必须对齐 `docs/architecture.md` 中的四维度 schema**，以便直接复用分析层与展示层。

---

## 三、字段 Schema 与风险预警逻辑

每条记录（主体 × 年份）的核心指标：

- **规模**：`total_assets`、`total_liabilities`、`asset_liability_ratio`（资产负债率）
- **盈利**：`operating_revenue`、`net_profit`、`roe`
- **偿债**：`ebitda_interest`（EBITDA 利息保障倍数）、`op_cf`（经营现金流净额）
- **流动性**：`current_ratio`、`quick_ratio`

**风险预警标签**（基于最新年份阈值自动触发）：

| 触发条件 | 标签 |
|----------|------|
| 资产负债率 > 70% | 杠杆偏高 |
| EBITDA 利息保障倍数 < 1.5x | 偿债保障偏弱 |
| 经营现金流 < 0 | 自我造血能力不足 |
| ROE < 1% | 盈利能力偏弱 |
| 流动比率 < 1.2 | 短债压力较大 |
| 速动比率 < 0.6 | 资产流动性弱 |

展示层（`index.html`）据此生成"风险预警汇总表"，并对资产负债率、杠杆、ROE 做可视化。

## 四、模拟数据（框架先行）

在真实数据不完整时，用合成数据先把整套分析框架跑通：

- 脚本：`data/mock/generate_mock_data.py`
- 数据：`data/mock/chengtou_mock.json`（8 家主体 × 2020–2024，固定种子可复现）
- 复现命令：

```bash
cd data/mock
python generate_mock_data.py
# 生成 chengtou_mock.json 与 仓库根目录 index.html（内嵌数据）
```

- 数据量级按评级分层（AAA > AA+ > AA > AA-），指标间保持合理相关性，仅用于演示，
  **不含任何真实披露、个人隐私或机密信息**。

---

## 五、分析 → 展示

- **展示层** `index.html`：自包含 HTML（内嵌模拟数据 + 内联 SVG，无 CDN），包含
  KPI 卡片、评级分布、杠杆对比、ROE/资产趋势、风险预警表。
- 部署：作为 GitHub Pages 站点（仓库 `main` 分支根目录），详见 `README.md` 首行链接。
- 接真实数据：把真实结构化 JSON 按相同 schema 替换 `index.html` 中的 `const DATA`，
  即可零改版切换到真实分析视角（注意：真实数据不进公开仓库）。

---

## 六、数据保护与隐私原则（强制）

1. **原始数据本地化**：`raw_files/`、`shandong_reports/` 仅存本地，绝不 `git add`。
2. **真实数据不上公仓**：`reports/`、任何含真实主体明细的文件均被 `.gitignore` 排除。
3. **模拟数据可公开**：`data/mock/` 与 `index.html` 仅含合成数据，可安全进仓库与 Pages。
4. **密钥隔离**：任何访问凭证（如 GitHub Token）只存在于环境变量，绝不写入仓库文件/脚本/日志/提交历史。
5. **上传前确认**：涉及原始 / 获取 / 隐私数据的上传，须经显式确认后方可执行。

#    将 PDF 放入本地 raw_files/，运行 scripts/parse_report.py
